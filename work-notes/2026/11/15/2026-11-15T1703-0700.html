What was done

  • ^ticket(756), consistency with the interpreter, in CI. Every program of the evaluator's own tests (316) also goes through hazel-jit when it compiles: 237 compiled, 207 agreed, none differ, none threw. The other 30 are ill-typed programs, where the interpreter stops at a failed run-time type check. Those are listed, and any other parting fails its test (trial/756-sweep, green).
  • ^ticket(757), Int and Nat exact. Measured first. Plain BigInt costs 1.5 to 11 times plain numbers; the hybrid used here (a number while it is a safe integer, a BigInt past that) costs 0.7 to 3.7 times. On the Witch, the compiled run per event went from 4-8 ms to 6-9 ms (trial/757-bigint, green).
  • ^ticket(759), invalid operations. Division by zero, a negative power and a bad int_of_string stop the compiled run, and the interpreter makes the stuck term. The harness counts that as agreeing (trial/759-divide-by-zero, green).
  • ^ticket(760), what hazel-jit leaves to the interpreter, written into its source: holes, the stepper's filters, and anything a stepper shows (a livelit in a probe drawer's stepper was drawn from JS; no longer); and now programs with type errors. The jit check on all six slides kept every compiled run (trial/760-stepper, green).
  • ^ticket(761), the limits, by the sweep's counts. Seventeen builtins, among them the string ones, the compare family and invert_ord (green). Partial application, f(a, _), is in CI.
  • ^ticket(762), why an undeclared result type costs 5 to 7 times. It is not unknown types: the statics infer a recursive function's type in passes. It is where the run-time type checks (ascriptions) sit: on each case arm's result, against once around the body.
  • ^ticket(763), a step limit. Each compiled function counts its call and reads the clock every 16384 calls. On the main thread a run has 50 ms or 50 million calls, then falls back to the interpreter. On the Witch: 7-10 ms per event, against 4-8 (trial/763-step-limit, green).
  • ^ticket(764), a crash in the interpreter, found by ^ticket(759)'s tests: int_mod, sint_mod, nat_mod and float_mod by zero raised InvalidBuiltin("mod") (on dev since at least 2025-07-02). The fix names each builtin itself and makes a builtin's error final, as an operator's is. PR #2825 to dev is open, green, and awaiting review.
  • ^ticket(730), the Tarot, hazeljs-oracles 0.0.7: every function's whole type declared, about 3.7 times faster (a Celtic Cross 173 ms to 46 in Node).
  • ^ticket(736), hazeljs 0.0.7: a JS value goes in by the function's declared type, so an array is a tuple where a tuple is wanted. Merged on hazelgrove/hazeljs main, its checks green; npm publish waits on Matthew's security key.
